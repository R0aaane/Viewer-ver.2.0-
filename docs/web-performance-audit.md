## ここまでの判断

サムネイル初回生成には実測で遅延がある。一方、今回の少数同時取得中はAPI全体の応答停止が再現しない。大規模・継続負荷やSafari利用時と同条件の結果までは保証しない。

起動時のJS再取得と、読込済み画面のスクロール・サイドバーのかくつきは分けて扱う。上記からSafariのGPU負荷やCPU負荷を断定することはできない。

**根本原因の特定は未完了。** 未取得の証拠は次のとおり。

- iPhone / iPadで問題が起きる瞬間のフレーム間隔と通信時間。
- 同時刻のホストCPU・ディスク負荷。SFTP専用アカウントにはプロセス照会の権限・シェルがないため、本測定では取得できない。
- 移行前の旧版 `1.0.210+220` のWeb配布物のエンジン情報。比較できたのは移行後の2版。

## 次に採取する証拠

[Safari診断手順](web-performance-diagnostics.md)で、無操作時と操作時の各20秒をiPhone / iPadで取得する。端末内のフレーム遅延とhealth応答の相関を、同時刻のメインPC側API測定・ホスト負荷と照合する。healthの遅延自体もブラウザーの実行待ちを含むため、単独ではサーバー原因と判定しない。
