# Web版のPDFページ編集

PDF詳細のプレビュー操作欄にある「ページを削除・編集」から開く。

- ページごとのサムネイルを確認し、削除、90度単位の右回転、ドラッグまたは上下ボタンで並べ替えできる。
- 元のページ番号を入力すると、そのページへ移動する。「編集をリセット」で未保存の変更を取り消せる。
- 「保存」の確認後に元PDFへ反映する。全ページ削除、同じページの重複、署名付き・暗号化PDFの編集は受け付けない。
- 復元アイコンからバックアップ日時を選ぶと、その時点のPDFに戻せる。復元前のPDFもバックアップする。

バックアップはホストの `MEDIA_SERVER_DATA_DIR/.pdf-edit-backups/<作品IDのハッシュ>/<バックアップID>/` に保存する。自動削除は行わない。復元はPDF本体を対象とし、DBを過去のコピーに置き換えない。

保存時は元PDFのSHA256で競合を検出し、バックアップの書き込みと編集後PDFの再オープン検証を済ませてから同一フォルダー内の一時ファイルを置換する。作品ID・タグ・お気に入り・評価を維持し、読書位置は残ったページへ対応付ける。復元時は現在の読書位置を復元後のページ数内に収める。

PDFの読み取り・描画と編集は同じロックで排他実行する。保存後はページ画像・サムネイル・PDF.js用データ・ページ数のキャッシュを更新する。別ブラウザーや別タブで既に開いているPDFは再読み込みする。

APIは既存のトークン認証設定を引き継ぐ。

- `GET /media/{media_id}/pdf-edit`: 現在のSHA256、ページ数、バックアップ一覧
- `POST /media/{media_id}/pdf-edit`: `revision` と保存順の `pages: [{page: 元の1始まりページ番号, rotation: 0|90|180|270}]`
- `POST /media/{media_id}/pdf-edit/restore`: 現在の `revision` と `backupId`

古いSHA256の保存・復元は409で拒否する。管理対象フォルダー外のパスや、利用者が指定した任意の保存パスは使用しない。
