# Safariの性能診断

1. 診断機能を含むWeb版 `1.0.230+240` 以降の配信を確認する。
2. iPhone / iPadで `http://100.100.18.16:8090/?perf=1` を開く。
3. 起動と画像読み込みが落ち着いてから「計測開始」。サイドバーの開閉・スクロール・画面移動を20秒行い、結果をコピーする。
4. 「再計測」を押し、同じ画面・同じ操作をもう一度20秒行う。再読み込みは挟まない。
5. 両方の結果欄を長押ししてコピーする。1回目・2回目とiPhone・iPadを区別して保存する。

1回目と2回目を比べることで、初回フォント登録等と繰り返し発生する描画負荷を分ける。必要なら追加で無操作時の20秒を測る。

通常のURLでは診断コードを読み込まない。`?perf=1` の場合だけ、同一サイトのhealthに約1秒間隔でGETし、フレーム間隔とリソース取得時間を採取する。結果は端末内に表示し、自動送信しない。PDF名・作品ID・トークン・リソースURLを結果に含めない。

## 解釈上の注意

- `frames` はrequestAnimationFrameの間隔。GPU描画時間そのものではない。`p95Ms` / `maxMs` / `framesOver50Ms` を操作前後で比べる。
- `health` にはネットワークとブラウザーのJavaScript実行待ちも含む。同時刻のメインPC側測定やホスト負荷と照合し、これだけでサーバー遅延と断定しない。
- `resources.thumbnail` / `pdf-page` は取得待ち時間。サーバー処理時間そのものではない。
- SafariでLong Tasks APIが未対応なら `longTasksSupported=false` になる。0件という判定に読み替えない。
- `rendererSignals.cpuFallbackWarnings` が1以上なら、FlutterがCPU描画への切り替えを警告している。0でもGPU正常を保証しない。警告が出ない別の描画問題までは検知しない。
- `resources.font` / `script` / `wasm` で追加読み込みの種類を区別する。取得時間とフォント解析・描画にかかった時間は別であり、フォント取得が速いだけでは解析負荷を否定できない。
- 描画警告はFlutter起動前から分類だけを記録する。警告本文は保存しない。「閉じる」でconsoleのラッパーを解除する。
- `renderProbeSeen=true` ならFlutter内部の計測も動作している。`renderPhases.layout` はレイアウト、`paint` は描画命令の構築、`frameworkFrame` はウィジェット更新から描画エンジンへのフレーム送信までの全体を測る。`frameworkFrame` は他の2段階を含むため合計しない。
- `slowRenderPhases` と `slowFrames` を時刻で比較する。内部段階が短いのにフレーム間隔だけ長い場合、段階外のJavaScript・エンジン・ブラウザー処理等の追加調査が必要。GPU実行時間を直接測る機能ではない。
- 内部計測は `?perf=1` の時だけ専用bindingを使い、通常URLでは従来のbindingを使う。「閉じる」で記録は止まるが、専用binding自体を解除するには通常URLで再読み込みする。
- バックグラウンド移行時は計測を停止する。`reason=tab-hidden` の結果は操作試験として使わず再計測する。
- `version` は配信中Webの版であり、既に開いているFlutterアプリの版を保証しない。更新後はページを再読み込みしてから測る。

ホストCPUはSFTP専用アカウントでは取得できないため、この診断に含まれない。必要ならホスト側のタスクマネージャー等でAPIプロセスとディスク負荷を同時確認する。
