# このPCのComfyUIで生成し、画像をホストへ送る

状態: 実装・実GPU検証済み（2026-11-17）。根拠: `LocalGenerationService`、ホームの `_openLocalGeneration`、`local_generation_live_test.dart`。

## 操作

1. Windows版のホームで「AI画像を生成」→「画像生成を開く」。必要ならComfyUIとローカル生成サービスが起動する。
2. 生成画像画面の「画像を生成」から、プリセット・描きたい内容・サイズ等を指定し、画面下部の「生成する」を押す。
3. 生成履歴で完了を確認する。完成画像の履歴をタップするとギャラリーへ戻る。
4. 画像のチェックを選び「ホストへ送る」。現在のクライアント接続先の生成画像専用ギャラリーへ画像をアップロードする。通常のPDFライブラリとは分離される。

転送は選択時に行う。失敗してもローカルの原本を保持し、再試行できる。既存の重複スキップ付きアップロードを利用する。生成処理を実行するPCとホスト接続設定は分離している。

## この環境

- ComfyUI: `E:\Program\AI\ComfyUI_windows_portable`。既存のembedded Pythonと`extra_model_paths.yaml`を使用。
- GPU: NVIDIA GeForce RTX 5060 Ti、VRAM約16GB。
- 初期プリセット: `waiIllustriousSDXL_v160.safetensors`、1024×1024、20 steps、CFG 5、1枚。v150も選択可能。
- 原本出力: ComfyUIの `output/PDFViewer`。この専用サブフォルダのみ取り込む。
- 接続・プリセット: workspaceの `data/local_generation/connection.json` と `presets.json`。生成原本・SQLiteも同ディレクトリ配下。これらはマシン固有のためGit対象外。

ComfyUIのlocalhost:8188と、既存FastAPIを別の保存先で起動するlocalhost:18890を使用する。後者は専用の認証トークンをWindowsのsecure storageに保持し、ホストの認証トークンを共有しない。アプリを閉じても起動済みのComfyUI・生成ワーカーは継続する。

現状はWindowsと既存workspace内のRelease配置に対応する。workspaceと`.venv`が必要。別PCへ移す際は接続設定の絶対パスとモデル名を実環境に合わせる。Webからこのローカル実行機能は起動しない。

## 確認結果

Windows profileアプリの生成ボタンから実GPUでPNGを1枚生成。既存クライアント設定のホストへ同じ画像を送信し、HTTP 200・importedCount=1を確認。ComfyUIの処理ログは初回モデルロード込み74.49秒。画像は1024×1024、約2.05MiB。原本の埋め込み生成情報を保持して転送する。

関連UI・Repositoryテスト22件成功。実画像を生成・転送するテストは `LIVE_COMFY_TEST=true` を明示した場合だけ動く。通常のテスト実行でホストへアップロードしない。

ComfyUIの追加ノードには既存のGroundingDINO・Triton不足やManagerのチャネル警告がある。今回使用する標準のCheckpointLoaderSimple・KSampler・VAEDecode・SaveImageでの生成は成功した。追加ノード全般の動作は未確認。

## 2026-11-17 更新

生成画像のホスト送信は `/generated/upload` を使い、通常のPDFライブラリ取り込み・整理処理から分離した。ホスト側もこのAPIを含む新版の起動が必要。未更新のホストへの送信は失敗し、ローカル画像は保持される。一覧の選択後に「削除」で削除済みへ移動し、削除済み表示から復元できる。物理ファイルの完全消去は行わない。従来の試験で通常ライブラリへ送った画像の移動・削除は自動実行しない。

## 2026-11-17 完全削除・タグ分類・LoRA（実装確定）

- 生成画像一覧で選択→「完全削除」、または詳細→画像の操作→「完全削除」。確認後に管理原本、サムネイル、生成情報、手動タグを物理削除する。登録時の内容と一致する管理対象ComfyUI出力元も削除する。変更済みの元ファイルは保護する。他ホストへ転送済みのコピーは対象外。
- 削除を先にジャーナルへ記録し、中断後はスキャンで再開する。digestの墓標を保持して同一画像の自動再取り込みを防ぐ。PDFライブラリDBには変更しない。
- タグ編集でアーティスト・生成タグ・手動タグ・キャラクター・シリーズを分類する。「アーティスト・生成タグから探す」に登録タグと件数を表示し、選ぶと一覧を絞り込む。生成情報の再解析でも手動タグは保持。ホスト送信では手動タグを追加として引き継ぎ、ホスト既存タグを消さない。
- ローカル生成画面を開く際にComfyUIのLoraLoaderからインストール済み一覧を取得する。標準txt2imgワークフローを複製した「イラスト（LoRAを使用）」で1個のLoRA、model/clip強度を指定可能。通常プリセット・独自ワークフローは保持する。モデル系列の互換性は利用者が確認する。プリセットは保存後の変更をAPIが再読込する。
- ホストでのタグ分類・完全削除・画像送信には新版サーバーが必要。ローカルサービスのみこのPCで更新し、外部ホストの配布は別途必要。

検証: サーバー回帰26件、Flutter関連3件が成功。完全削除・タグ転送の最終確認13件も成功。LoRAはComfyUIで78候補を確認し、Flanvia_Style_ILをmodel/clip強度0.5で使用して1024×1024画像を実生成し、生成情報の一致を確認（実機テスト成功）。

## 2026-11-17 接続停止からの復旧（確認済み）

ComfyUIの8188番ポートが待受しておらず、ローカルAPIだけが動いて送信結果を照合し続けていた。ComfyUIを既存環境で再起動し、元ジョブがキュー・履歴に存在しないことを照合した後、保存済みの同じ条件で再生成して画像登録まで確認した。ComfyUIが停止した原因そのものは未特定。

ローカル画像生成画面に「ComfyUIを起動・再接続」を追加。再接続はサービス起動と履歴更新のみで、自動的に再送信しない。停止中は再接続を促すメッセージを表示する。HTTP 5xxが継続した場合にも送信後のタイムアウトを適用する。接続復旧後も失敗となったジョブは内容を確認して利用者が再生成する。

検証: 接続停止・二重送信防止・HTTP 503のタイムアウトを含むサーバーテスト11件、Flutter関連4件が成功。保存済み条件での実生成・原本保存を確認。ポート待受不在の証拠とキュー・履歴照合が今回の根拠であり、未知のプロセス停止原因を断定しない。

## ホスト集約方式（2026-11-17 確定）

生成はこのPCのComfyUI、保存・閲覧の集約先は既存ホストとする。ホームの「生成画像」はホスト側APIへ接続し、ローカル側は「このPCの生成・送信状況」と明示する。PDF解析から開いた生成画面にも「ホストの生成画像」を設ける。

ローカルAPIの `generated_transfers` テーブルに画像ID・接続先識別子・送信状態・再試行時刻を記録し、生成完了画像を `/generated/upload` へ自動転送する。認証情報はアプリの既存SecureStorageからローカルAPIへ渡し、そのプロセスのメモリだけで保持する。DB・ログへトークンを保存しない。ローカルワーカーの再起動後はアプリで生成画面を開くと再設定し、未送信分を再開する。

ホスト停止・認証失敗・受信機能未設定時は原本を保持して再試行し、送信状態を生成履歴へ表示する。重複転送はSHA256で冪等に処理し、手動タグはホストの既存タグへ追加する。送信後もローカル原本は保持する。ホストで削除した画像をローカルから無条件に再送することはしない。

ホストにComfyUIは不要。既存の生成ライブラリ指定がなければ、認証が有効なホストのDATA_DIR配下に `generated_inbox` と `generated_library` を初期化して画像受信・一覧APIを提供する。既存指定がある場合はその保存先を維持する。実際のライブラリパスは既存の保守用host_settings.jsonにも記録し、バックアップ対象を維持する。

生成モデル・ワークフロー・PDF本体・PDFタグDBはホストへ転送しない。画像とその手動タグだけを送る。

ホストが既存のtailnet_without_tokenポリシーを使う場合はその方式を維持し、空のBearerヘッダーを付けない。Bearer・デバイストークンが設定されている場合は既存資格情報を利用する。Tailscaleポリシーや公開ネットワーク制限をこの機能から変更しない。
