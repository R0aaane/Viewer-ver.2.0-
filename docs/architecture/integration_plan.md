# 段階別の統合計画

既存の閲覧・検索は現在の入口を使い続ける。生成ライブラリは Home に追加する明示的な接続先とし、アプリ起動時の必須接続にしない。以下は承認前の設計案。各段階で差分・試験結果・復旧手順を報告して停止する。

| Phase | 最初の実装単位と完了条件 |
|---|---|
| 1 安定性 | 合成素材と隔離DBで Windows の列挙回数・次ページ時間、画像メモリを計測。Android改名は実機で確認。再現した問題ごとに回帰テストを先に作り、最小修正。同じデータで改善値とタグ・閲覧互換を比較 |
| 2 取り込み | 既存 FastAPI に認証必須の生成ライブラリ用ルーター、専用SQLite・ワーカーを追加。ComfyUIの出力を読み取り専用で扱い、ファイルサイズ・更新時刻の安定、コピー前後の一致、デコード可否とSHA-256を検証。同一ボリュームの一時ファイルから原子的に配置し、DB登録・サムネイル・通知の段階を永続化。各境界でプロセスを停止し、再起動後に重複／欠損ゼロを確認 |
| 3 整理・検索 | workflow JSONとAPI prompt原文を保存し、ノード型と接続を辿って正負prompt、seed、steps、CFG、sampler、scheduler、checkpoint、LoRAを抽出。未知ノードも原文保持。専用APIで全文検索（FTS5の利用可否を実環境で確認）、日時・タグAND/OR/NOT・並べ替え・お気に入り・分類・一括編集を実装。異なる構成のfixtureで再解析後も手動タグを照合 |
| 4 Flutter | MediaRepository・RemoteMediaRepository と既存グリッド／詳細画面の取得・表示部分を再利用。生成固有の属性・検索は追加インターフェースへ。接続状態、ページ取得、再試行、取得の重複排除、バイト上限と追い出し、タグの期待バージョン不一致時の再読込を実装。サーバー停止中に従来のローカル画像・PDF・タグを操作して検証 |
| 5 生成 | 対象ComfyUIのバージョンとAPIを公式実装・隔離ホストで確認。サーバー管理のプリセットで入力項目・範囲・モデルを許可リスト化。端末別Idempotency-Keyと入力指紋を永続化し、/prompt、WebSocket、/history、/view と取り込み台帳を連携。queued → submitting → running → importing → completed、失敗・取消要求・取消完了を永続化。送信結果不明なら履歴照合し、盲目的に再送しない。所有権を確認できない実行を中断しない |
| 6 接続 | ComfyUI は localhost、FastAPI はホスト側VPN経由の到達制御、端末別・失効可能なトークンと認証付きイベント接続。サーバー設定のルート配下にファイル操作を限定。LAN・外出先・失効端末で許可／拒否を確認してから接続対象を拡大 |
| 7 同期・復旧 | 単調増加カーソルで新規・タグ・お気に入り・改名・削除・復元を配信。更新と変更履歴を同一トランザクションに置く。バックアップを別環境で復元し、容量不足・DBロック・通信断・ホスト再起動・生成タイムアウトの復旧試験を実施 |

Phase 1で必要なものは測定用フォルダと試験用DB。実データのコピーは利用者が指定した場合のみ使用する。Phase 2以降に専用ライブラリの保存先、ComfyUI版とプリセット、端末・VPN構成を確認する。
