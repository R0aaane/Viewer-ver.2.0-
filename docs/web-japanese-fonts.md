# Web版の日本語フォント先読み

1.0.231+241ではNoto Sans JPのRegular/Boldをアプリのアセットに同梱し、設定読み込みと並行して取得する。両方をFlutterへ登録してからrunAppし、日本語フォントのない画面を先に表示しない。WebテーマとAppBarに同じファミリーを指定する。Windows等のテーマは既存の既定フォントを維持する。

タグ・入力欄・ドロップダウンの独自スタイルにも明示的に適用する。本文だけの指定では、タグ等が既定フォントへ戻り、追加の日本語フォント取得が残ることをブラウザー検証で確認した。

- 可変TTFの全字形を保持して400/700へ固定し、Web用WOFF2へ圧縮。合計約4.44MiB。初回の起動時転送は増えるが、操作のたびに標準日本語のフォント断片を補完する処理を減らす。
- 元フォントの固定コミット・SHA256・変換情報はassets/fonts/SOURCE.json、再配布ライセンスは同OFL.txt。Webのライセンス一覧にも登録する。
- フォント取得に失敗した場合は従来のフォントへ戻して起動する。まれな漢字・絵文字など、同梱フォントに含まれない文字には引き続き補完が必要。
- 通常URLにも適用する。診断専用の変更ではない。PDF・DB・ホストの保存先や設定は変更しない。

Safari実機での確認:

1. 更新後にページを再読み込みし、作品名やサイドバーに□表示が先行しないことを確認。
2. 同じ作品一覧・サイドバー・画面移動を操作し、停止が減ったか確認。
3. 必要なら ?perf=1 で再計測。同梱フォントは計測開始前に登録するため、通常の日本語表示でresources.fontが増え続けないこと、slowRenderPhases/slowFramesが改善することを確認する。

フォントの補完処理は負荷の候補であり、これだけで全停止の原因を証明したわけではない。実機の改善幅は配信後の比較結果で判断する。

ローカルRelease版のChrome検証では、通常・診断の両モードで同梱フォント2件の取得成功、外部日本語フォント取得0件、解析エラー0件を確認。Safariの実測結果として扱わない。
